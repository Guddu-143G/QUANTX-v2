# Risk Engine Architecture

The Risk Engine is the most important component of the QUANTX platform. It has absolute authority over every algorithmic strategy and manual order. **The Risk Engine must always be able to say NO.**

## 1. Engine Hierarchy

The Risk Engine is divided into four sub-services:

1. **PreTradeRiskEngine**: Evaluates orders before submission to the broker.
2. **RealtimeRiskEngine**: Continuously evaluates open positions and exposure against live market data.
3. **PortfolioRiskEngine**: Manages macro constraints (sector exposure, overall drawdown, portfolio VaR).
4. **EmergencyRiskEngine**: Handles circuit breakers, kill switches, and catastrophic anomalies (e.g., broker disconnects).

## 2. Pre-Trade Risk Checks

Before any signal generated by the Strategy Engine becomes an active order, it must pass EVERY mandatory check. If ANY check fails, `ORDER = BLOCKED`.

- **Cash & Margin Check**: Is there enough capital?
- **Position Size Check**: Does the new size exceed `max_position_weight`?
- **Sector Exposure Check**: Does this push the sector above `max_sector_weight`?
- **Volatility Check**: Is the asset currently too volatile relative to the risk policy?
- **Liquidity Check**: Is the order size unreasonable relative to Average Daily Volume (ADV) or current market depth?
- **Data Quality**: Is the market data fresh? Are there timestamps gaps?

## 3. Position Sizing Logic

QUANTX does not use simplistic fixed-percentage allocations (e.g., "always buy 10%"). It uses risk-based sizing.

1. **Calculate Position Risk:** `Entry Price - Stop Price`
2. **Calculate Allowed Capital Risk:** `Portfolio Value × Risk Budget` (e.g., 0.5% of total portfolio)
3. **Determine Size:** `Allowed Capital Risk / Position Risk`
4. **Apply Constraints:** Cap the size according to liquidity, maximum position weight, and broker quantity limits.

## 4. Stop-Loss Engine

A stop-loss is treated as a first-class service with a two-layer defense mechanism.

### Layer 1: Broker-Side
Whenever supported by the broker, a protective stop order is physically placed on the exchange.

### Layer 2: QUANTX Monitoring
QUANTX continuously tracks the market price and the state of the broker's protective order. If the protective order disappears (e.g., cancelled manually by the user or rejected by the broker), the Risk Engine triggers an alert and initiates reconciliation.

### Supported Stop Types:
- Fixed percentage stop
- ATR stop
- Volatility-adjusted stop
- Trailing stop
- Break-even stop
- Time-based exit

**Trailing Stop Rule:** Never move a protective stop backward to increase risk, unless an explicitly defined statistical strategy mathematically requires it (which is rare).

## 5. Portfolio-Level Constraints

Individual position stops are insufficient. The PortfolioRiskEngine enforces:
- Daily Loss Limit (e.g., max 1% loss per day)
- Weekly Loss Limit
- Maximum Portfolio Drawdown
- Maximum Leverage (Default: 1.0x / Cash only)

When a portfolio constraint is breached, QUANTX blocks new entry trades and alerts the user.

## 6. Circuit Breakers

The EmergencyRiskEngine automatically triggers circuit breakers under anomalous conditions:
- **Broker Disconnected**: Pause new entries, preserve protective states.
- **Market Data Stale**: Mark data as stale, block new entries.
- **Order Rejection Spike**: If the broker rejects multiple orders rapidly, pause automation.
- **Unexpected Slippage**: If execution costs far exceed expectations, halt strategy.
- **Duplicate Order Detection**: Prevent runaway loops.
- **System Clock Drift**: Halt if local server time significantly drifts from exchange time.
